# NRO runtime assets

Runtime art lives under `public/assets/nro`. Keep the folder at the web root aligned with this taxonomy:

| Folder | Contents |
| --- | --- |
| `character/td`, `character/nm`, `character/xd` | Earth, Namek and Saiyan character action frames (`dung`, `di`, `bay`, `tancong`, `chuong`) |
| `monster/<slug>` | Authored monster frames grouped by monster and action |
| `monster/generated` | Generated fallback monster art and source animation frames |
| `npc/portraits`, `npc/generated` | Art pack NPC images and generated NPC fallback sprites |
| `skin` | Costume and appearance item art |
| `skill/icon`, `skill/animation/<race>/<skill>` | Skill icons and optional three-frame skill animations |
| `boss` | Boss art |
| `map/backgrounds`, `map/tiles`, `map/data` | Map visuals, tiles and runtime map/catalog data |
| `trangbi/td`, `trangbi/nm`, `trangbi/xd` | Equipment icons grouped by planet |
| `items/bua`, `items/nangcap`, `items/ngocrong`, `items/khac` | Consumables, upgrade materials, Dragon Balls and other items |
| `data/manifests` | Runtime lookup manifests; generated by the asset scripts |
| `ui` | Shared UI textures |

## Update pipeline

Run `npm run assets:nro-redraw` from `client/` to prepare source data and regenerate runtime art. The `dev` and `build` scripts run the same preparation steps automatically. Keep original art packs and extracted source archives outside `public/`; only files copied into `public/assets/nro` are sent to players.

When adding a new asset family, update its generator/import script and the loader URL together. The generated manifests in `data/manifests` and `src/generated/nroArtPackManifest.js` are lookup outputs, not hand-maintained source files.
